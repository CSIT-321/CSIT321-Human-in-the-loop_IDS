## Challenges to the team's assumptions
- Fact 1 is now only true before `scripts/materialize_flow_queue.py` runs: `operational_queue.queue_page` has no source filter (`hitl-ids/apps/api/operational_queue.py:9-12`), so the materialized flow alerts do appear in `/api/v2/alerts` and the default `workScope=active` view. The remaining defect is that they are unactionable (S3-01), not invisible.
- Fact 2's real gate is the existence of `operational_system_routing`, not the source kind. The `/admit-tier1` action is allowed for a flow alert and does not create that row, so manual admission still leaves it unclaimable and verdict-less (`hitl-ids/packages/detection/analyst_work.py:83-86`, `hitl-ids/packages/detection/analyst_verdict.py:64-67`).
- Fact 3 is structural, not a policy accident: the recommendation is computed at the only admission-time call with a context that can only contain destination-IP `assetCriticality`; the result is then hard-coded away at `hitl-ids/packages/detection/system_routing.py:101` and omitted from the audit at 113-119.
- Fact 4's 1/165 replay result does not show that context rules work: `hitl-ids/scripts/protocol_v3_1/worker.py:93-97` seeds the synthetic facts after `admit_external`, so they reach selective review but never the router. The one escalation is the context-free unknown-classification rule.
- Fact 5's "Not provided" confidence is a display mapping issue, not data loss: the 100.0% legacy value survives as `LegacySourceProvenanceV2.legacy_fusion_confidence` (`hitl-ids/packages/detection/adapters/operational_v2.py:40-42`) and `originalDetectorFields.legacyFusionConfidence` (`hitl-ids/packages/detection/adapters/current.py:61`); `hitl-ids/packages/detection/adapters/current.py:24-32` deliberately does not copy a fused confidence into `detector_confidence` for corroborated/override alerts. Restore the lost value by displaying the preserved legacy-fusion field.
- Fact 7 is already representable from CEF fields: `evidence_class == 'corroborated'` plus `detection_score >= 80` is exactly rule-and-model agreement plus the score floor, and `hitl-ids/packages/detection/adapters/current.py:33-41` preserves the rule classes and ML class. No new inference is needed; the missing pieces are a rule in the policy and a source-neutral routing path.
- "Foolproof" is not met by the current error path: classification/version/storage errors abort the whole admission transaction instead of degrading to human review, and uncertainty (unknown classification) is the one condition that auto-cases. The current failure mode is fail-closed but not human-fallback.
- One concept has several names: canonical external evidence is `external_signature` (`hitl-ids/packages/detection/adapters/suricata.py:60`) while the admission proposal is `external_rule` (`hitl-ids/packages/detection/adapters/admission_policy.py:19`); `route_class` and `handling_route` express different things; `tier2_recommended` and `route` are not the same decision. The design documents cannot define these consistently until the candidate workflow is made real.
