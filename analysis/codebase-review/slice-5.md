## Module map (for the design documents)

- hitl-ids/apps/api/routes.py — Legacy S10b REST surface: queue/alert reads, verdict feedback, triage status/owner/notes, dashboard, admin IP reports, audit, guardrails, evaluation reads — legacy.
- hitl-ids/apps/api/auth.py — bcrypt sign-in, HS256 token mint/verify, `Principal`, `require_role` — shared (the auth boundary for both generations).
- hitl-ids/apps/api/deps.py — per-request SQLite connection selection/open/migrate and the single `ApiError` envelope — shared.
- hitl-ids/apps/api/mappers.py — legacy DB rows to contract wire shapes (queue rows, evidence panels, guardrail chains) — legacy.
- hitl-ids/apps/api/main.py — app factory, CORS, error handlers, router mounting, replay-controller startup — shared.
- hitl-ids/apps/api/read_only.py — aliases for the non-migrating connection and JWT principal — shared.
- hitl-ids/apps/api/workspaces.py — global workspace selection in `control.db` plus replay prepare/reset/advance/playback — V2.
- hitl-ids/apps/api/workspace_routes.py — HTTP commands for workspace inspection and activation and replay lifecycle — V2.
- hitl-ids/apps/api/presentation_replay.py — builds and advances the frozen V3.1 replay database from committed inputs — V2.
- hitl-ids/apps/api/alert_stream_routes.py — authenticated, workspace-bound SSE stream of committed operational arrivals — V2.
- hitl-ids/apps/api/admin_current_routes.py — read-only current admin overview, governance, users and audit — V2.

## Challenges to the team's assumptions

- "A client can no longer claim to be the admin by writing a header" (auth.py:5-7) is only true for headers: with the committed `DEV_SECRET` (auth.py:38) a client can mint a token naming `admin`/`system_admin`, and `_decode` accepts it with or without an `exp`.
- "The V2 web console replaced the legacy analyst pages" is true for the web client, but not for the API: `main.py:88` still mounts the legacy verdict write, and it is the weaker path (S5-01, S5-06). The rehearsal script (`scripts/rehearse_demo.py:108`) is a live caller, so the legacy surface cannot be dismissed as dead code.
- "Every request snapshots the active workspace" (workspaces.py:3-6) is accurate per request but does not give per-user isolation: the selection is one row for the whole product (S5-04), and authentication resolves the token in whichever database that row names (auth.py:205-208), so user existence itself changes with the workspace.
- The role document says "evaluator may only read" and "hiding buttons is not the authorization boundary" (docs/authenticated-tier-routing-workflow.md:24-26); the legacy feedback route contradicts both (S5-01).
- Path handling is not where the risk is: `workspaceId` is allowlisted (workspaces.py:166-167) and `runId` is alnum-gated before the path join (routes.py:672-674), so no traversal was found. The real path failure is the missing-selected-file lockout, which leaves the API with no in-app recovery (S5-03).
