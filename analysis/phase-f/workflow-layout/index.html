The chain

Each box names the stage, its input, the table it writes, and the screen where an analyst sees it. Priority comes from the native severity table at admission; the attack class only decides who handles the alert.

Retired from the demo

CICIDS2018 flow lane (code present, not used)

CSV flow records, CICFlowMeter features, XGBoost scoring, fusion, alert groups, E1/E3 routing.

Why it is out: it starts from a labelled research dataset, not from packets. Its scores are model opinions about research features, and its demo screens show alert groups that Suricata never produced. Keeping both lanes doubled every count and made two versions of the same event.

What remains in the repository: packages/detection/fusion/, flow_routing.py, scripts/materialize_flow_queue.py and their tests. They are not part of this workflow and must not appear in the demo or the guide.

One consequence to decide: the product currently refuses to hold both lanes in one database (packages/detection/system_routing.py:70-75). A Suricata-only database is unaffected, so the demo can now be a single database. The mixed-lane case must be resolved before any deployment runs both detectors.
