6. How the reranking is performed

A verdict does two things. It moves its own alert, and it feeds the family gate. The gate is what stops one analyst's mistake from spreading across a whole family of similar alerts.

StepRuleValue
1. Own delta (C1)confirm: +k·w, dismiss: −k·(1−w); k = 30, w = severity / 10own alert moves at once
2. Family keyattack class + destination port + protocol + first rulee.g. Web Attack · 80 · tcp · —
3. Gateat least 3 learning verdicts, dominant share ≥ 0.67 (strong ≥ 0.80), no tie3 of 3 opens
4. Applied adjustmentclamped to −30 … +20; critical floor 70, infiltration floor 75never past the floor
5. Placementmembers without their own verdict get the adjustment; band offset moves the queue classone band per confirmation
6. Queue ordereffective score = routing priority + (combined − detection)row shows the same number

The alert that received the verdict shows both numbers. Its detector score stays 52.39; the queue row now reads P3 / 22.39, because the row displays the score the order uses: routing priority plus the verdict delta. Nothing is written back to the triage state, so the stored routing value and the shown value cannot disagree.

Why the gate exists. A single verdict is an opinion. Three that agree are evidence. A tie, or a split under 67 %, leaves the family closed and the adjustment at zero. Escalate and needs-investigation verdicts do not count toward the learning categories.

7. What this page does not show

  • R2 is large by design. 10,776 unflagged flows each become one low-priority Tier 1 item (decision D4).
  • R1's stored reason is older than its group. A group is routed once, when its first members arrive; the reason quotes the size at that moment.
  • Review is automatic in the replay. Staging review is recorded in the preparing Admin's name. In Operational, an analyst makes each decision.
  • Recorded traffic, not live traffic. The model was trained on this testbed.
